# 训练与验证指南（二分类 · 36×36 输入）

面向"只有一批实拍数据"的使用者，回答四个问题：**数据集怎么指定、用什么格式输入、怎么训练、结果怎么验证 / 可行性怎么判断。**

> 当前任务：给定 36×36 灰度 ROI（目标居中、外圈为背景），二分类判定**是否为无人机/飞机**。模型为 `DroneNet`（~7.6 万参数），损失 `BinaryFocalLoss`。

---

## 1. 数据集如何指定？

通过命令行参数二选一：

| 场景 | 参数 | 说明 |
|---|---|---|
| **没有实拍数据**（先跑通管线/预训练） | 不传 `--data-root` | 程序用**在线合成**数据，无限量、无需准备文件 |
| **有实拍数据**（微调/正式训练） | `--data-root <根目录>` | 程序读取 `<根目录>/train` 和 `<根目录>/val` |

```bash
# 合成数据（无需任何文件）
python scripts/train.py --epochs 30 --n-per-class 5000 --device cuda

# 实拍数据（指向你的数据根目录）
python scripts/train.py --data-root data --epochs 15 --device cuda
```

---

## 2. 数据集格式（输入规范）

### 目录结构（二分类，负样本无需细分）
```
data/
├── train/
│   ├── drone/*.png        # 正样本：飞机/无人机 ROI
│   └── non_drone/*.png    # 负样本：天空/云边缘、杂波等，混入即可
└── val/
    ├── drone/*.png
    └── non_drone/*.png
```

- **标签由"子文件夹名"决定**，不需要任何 CSV/标注文件。
- **正类文件夹名**（不区分大小写，命中即为正样本）：`drone / plane / target / uav / positive`；**其余任何文件夹名都算作负样本**。
- 也兼容旧的四类布局 `drone / sky_edge / cloud_edge / background`——此时仅 `drone` 为正，其余三类自动并入负类。

### 单张图片要求
| 项目 | 要求 |
|---|---|
| 格式 | `.png / .jpg / .jpeg / .bmp` |
| 通道 | 任意，读取时自动转灰度（取亮度 Y） |
| 尺寸 | **任意**；程序会 resize 到 **36×36**（`INTER_AREA`） |
| 构图 | **目标大致居中，外圈约 8px 为背景**（与合成一致，供局部背景估计） |

### 两个必须遵守的点
1. **负样本要含"硬负例"**：天空边缘、云层边缘、远处景物暗斑等——否则模型只会区分"飞机 vs 纯天空"，遇到边缘干扰会误报。
2. **按视频场次/场景划分 train/val**，同一场景的帧不得跨集合，否则验证指标虚高。

---

## 3. 如何训练？

### 推荐配方（数据量小，如 ~300 张）：合成预训练 → 实拍微调
```bash
# Step 1：合成预训练（无限数据，先把特征学出来）
python scripts/train.py --epochs 30 --n-per-class 5000 --device cuda --out runs/synth_pre.pt

# Step 2：实拍微调（加载 Step1 权重，用小学习率）
python scripts/train.py --data-root data --init-from runs/synth_pre.pt \
    --epochs 15 --lr 1e-4 --device cuda --out runs/finetune.pt
```

### 常用参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `--data-root` | 空 | 实拍数据根目录；空=在线合成 |
| `--init-from` | 空 | **预训练权重路径，用于微调**；空=随机初始化 |
| `--n-per-class` | 3000 | 合成数据每类样本数（仅合成模式） |
| `--epochs` | 10 | 训练轮数（微调建议 10~20，小学习率） |
| `--batch-size` | 256 | 批大小 |
| `--lr` | 3e-4 | 学习率；**微调建议降到 1e-4 ~ 5e-5** |
| `--no-handcrafted` | 关 | 消融开关：去掉手工特征分支 |
| `--device` | 自动 | `cuda` 或 `cpu` |
| `--out` | runs/dronenet.pt | 最优模型保存路径 |

> 微调时注意：**`--no-handcrafted` 的设置要和预训练时一致**，否则权重不完全匹配（程序会打印 missing/unexpected 数量提示）。

## 4. 结果如何验证？

训练结束后会打印一份二分类报告，读懂它即可：

```
=== 二分类: 是否无人机 ===
  precision / recall / f1 / far_per_roi        # 在阈值 0.5 下的指标
=== 无人机检测 (AUC / AP / 固定 FAR 下召回率) ===
  auc / ap / recall@far0.01 / recall@far0.001 / recall@far1e-05
```

| 指标 | 含义 | 怎么看 |
|---|---|---|
| `precision` | 判为无人机的里有多少是真的 | 高=误报少 |
| `recall` | 真无人机里抓回来多少 | 高=漏检少（业务更看重） |
| `far_per_roi` | 每个 ROI 的虚警率 | 越低越好 |
| `auc` | 阈值无关的整体区分能力 | 越接近 1 越好 |
| `recall@far1e-4` | **虚警率压到 1e-4 时的召回率** | 最贴近业务的指标 |

**选工作点（部署阈值）**：按业务允许的虚警率选。例如要求 FAR≤1e-4，就看 `recall@far1e-4` 对应的分数阈值作为部署阈值；`recall@far*` 越高说明在低虚警下仍能保住召回。

## 5. 如何验证模型可行性？（验收清单）

按这个顺序走，能较快判断"这条路行不行"：

1. **规则基线对照**（证明学习法确实强于传统法）
   ```bash
   python scripts/baseline_eval.py --n-per-class 500
   ```
   把它的 F1/AUC 与 CNN 对比，CNN 应显著更高。若 CNN 没明显优势，说明管线/数据有问题。

2. **合成冒烟**：合成预训练后，`recall@far1e-3` 应明显可用（合成数据只验证管线，不代表实拍水平）。

3. **实拍验证（关键）**：微调后，**必须看 100% 实拍的验证集指标**，别看合成集。
   - 可行性参考线（初始目标）：实拍 AUC ≥ 0.9、`recall@far1e-3` 达到业务可接受水平。
   - 数据少时用 **K 折交叉验证**（K=5，按场景分组）报均值±标准差，别信单次划分。

4. **消融实验**（验证设计有效性）：
   ```bash
   python scripts/train.py --data-root data --no-handcrafted ...   # 去手工特征
   ```
   对比保留/去掉手工特征的差异，判断该分支是否真正有帮助。

5. **失败案例分析**：把验证集里的误报/漏检样本（Top-N）挑出来人工看，归因（过曝？目标太小？边缘恰好闭合？），回头调合成管线参数域或补数据。

6. **鲁棒性测试**：对验证集注入额外噪声/模糊/亮度漂移，看性能-退化曲线是否平缓。

## 6. 模型正确性验证与 ONNX 导出

### 6.1 训练产物冒烟检查（理论运行验证）
```bash
python scripts/validate_model.py --ckpt runs/finetune.pt
```
不依赖真实部署，用合成数据检查四件事：**权重能否严格加载**（架构一致，strict）、**输出是否为合法概率**（形状 (N,)、取值 [0,1]、无 NaN/Inf）、**正样本均分是否高于负样本**、**合成集 AUC 是否 > 0.5**。全部 PASS 退出码 0，任一 FAIL 退出码 1（可接入 CI）。

### 6.2 ONNX 导出
```bash
python scripts/export_onnx.py --ckpt runs/finetune.pt --out runs/dronenet.onnx
```
- 输入：`roi (batch,2,36,36)` + `feat (batch,8)`；输出：`prob (batch,)` —— **已含 sigmoid，直接是无人机概率**；
- 批大小动态可变，opset 17；导出后自动做 onnx 结构校验。

### 6.3 ONNX 一致性验证（关键步骤）
```bash
python scripts/verify_onnx.py --ckpt runs/finetune.pt --onnx runs/dronenet.onnx --tol 1e-4
```
验证流程三步：
1. **输入数据准备**：合成真实分布样本（覆盖 4 类语义）+ 随机输入（极端值域，边界覆盖），同一批输入分别喂给两个模型；
2. **推理结果对比**：PyTorch 与 ONNX Runtime **统一在 CPU** 上推理（消除设备差异），逐样本比较概率输出，并比对 0.5 阈值下**分类决策是否完全一致**；
3. **误差容忍范围**：统计 `max_abs_diff` / `mean_abs_diff`，默认 `tol=1e-4`（float32 数值精度损失量级）；超差或决策不一致即 FAIL，并打印最差样本的两侧输出便于定位。

## 附：当前合成数据口径（供对照实拍采集）
- 目标像素尺度：2×2 ~ 18×18（含极小目标），size-aware 模糊保证极小目标可学；
- 正样本目标居中，外圈 8px 背景环带；
- 所有类别走同一退化链（模糊/噪声/亮度漂移），负样本含天空边缘、云层边缘、纯背景三种以保证多样性。
